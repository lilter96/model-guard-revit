# Архитектура и инварианты

## Границы и зависимости

`Core/netstandard2.0` — DTO, геометрия, BVH, виртуальное разбиение, Дейкстра, правила параметров, fingerprint, миграции, схема и экспорт. Ссылок на Autodesk/WPF нет.

`Presentation/netstandard2.0` — команды, ввод настроек, фильтрация, состояния выбора, доступность действий и ru/en ресурсы. Тестируется на Linux отдельно от WPF.

`Revit` — чтение снимка, storage, атомарные записи марок, генерация схем и обработка отказов транзакций. `RevitRoutingDocument` реализует порты ядра.

`UI` — WPF разметка на C#, bindings, оконные события и file picker. Команды плагинов собирают зависимости и исполняют намерения после закрытия окна.

`RoutingWorkflow` получает IRoutingSnapshotSource и IRoutePlanRepository в конструкторе. `Run` возвращает план и исходный снимок для отчёта. `Save` проверяет формат и актуальность до вызова repository. В тестах fake source меняет геометрию между расчётом и сохранением; проверяется отсутствие записей.

DTO изменяемые для JSON/адаптеров; это не immutable domain model. Результат копирует настройки/точки пути, виртуальное разбиение не меняет входной граф. Внешний код должен считать снимки и результаты read-only. Fingerprint проверяет исходные данные и не является цифровой подписью результатов.

## Контекст Revit

Все API-вызовы выполняются синхронно на потоке Revit внутри IExternalCommand. ViewModel не содержит Document/Element/Connector. CancellationToken поддерживается ядром и reader; кнопки отмены фонового расчёта нет, расчёт остаётся синхронным. Для modeless окна нужен ExternalEvent и отдельный жизненный цикл документа. Task.Run с Revit API не используется.

## Геометрия и топология

1. Узлы — физические End-коннекторы лотков/фитингов, ID = Owner.UniqueId + Connector.Id.
2. Внутреннее ребро лотка имеет фактическую длину LocationCurve; геометрия для отображения — Tessellate с ориентацией From → To.
3. Фитинг соединяет пары коннекторов с оценкой по прямому расстоянию.
4. Между элементами связь появляется только через AllRefs + IsConnectedTo. Примерное совпадение координат не соединяет граф.
5. Прямой лоток получает SupportsInteriorAttachment. Длина и геометрия должны соответствовать прямому сегменту; идентификаторы рёбер уникальны.
6. BVH индексирует прямые сегменты и все точки коннекторов. Query использует AABB lower bounds, 3D-проекцию и ограничение радиуса. Worst case O(V+E), дерево ускоряет типичные запросы, а не гарантирует O(log N) для любой геометрии. Построение текущей реализации с сортировкой каждого уровня — O(N log² N).
7. Все точки подключения проецируются до расчёта. По каждому сегменту они сортируются, объединяются с допуском 1e-12 по параметру и разбивают ребро на подучастки. Исходная геометрия RVT не меняется.
8. Дейкстра выполняется один раз от виртуальной точки контроллера. Двоичная куча, неотрицательные веса, устаревшие записи, стабильные tie-breaks. Predecessor хранит конкретное ребро, чтобы параллельные варианты восстанавливались правильно.
9. Путь возвращается device → controller с обеими прямыми подводками. При превышении пользовательского предела CableLimitExceeded сохраняет путь для анализа.

Дейкстра: O((V+E) log V). Максимальный общий этап привязок зависит от геометрии, количества запросов и BVH. Компоненты определяются union-find. Метрики включают исходные узлы/рёбра, виртуальные узлы, компоненты и время расчёта.

## Актуальность и JSON

SHA-256 вычисляется над бинарной канонической последовательностью: версия формата fingerprint, сортированные узлы, ориентированные канонически рёбра/геометрия, контроллер, отсортированные устройства/марки, все настройки. Длина строк кодируется BinaryWriter, поэтому неоднозначность разделителей отсутствует; -0 нормализуется. Порядок коллекций не меняет hash. При изменении алгоритма/контракта fingerprint его version prefix нужно повысить.

Перед сохранением снимок перечитывается через source. Current разрешает запись; Stale/Unknown запрещают. Внутри Revit проверка и запись выполняются в одном синхронном API-контексте; это не общий протокол атомарности для произвольных многопоточных repository.

Revit Schema постоянна и содержит строку Json. v1 хранил футы, переносится в метры со статусом Legacy. v2 сохраняет длины, но не имеет пути/подписи; после миграции геометрия остаётся пустой, актуальность Unknown. При отсутствии времени старого расчёта используется неизвестная дата (MinValue), а не дата миграции. v3 содержит геометрию, привязки, fingerprint, диагностику и метрики. Будущая версия и повреждённые/неоднозначные данные блокируют запись. Input и output ограничены 8 миллионами символов; MaxDepth 64; TypeNameHandling.None.

## Контракт параметров

JSON AuditProfile v1 проверяется до чтения модели. Правило выбирает имя либо GUID (GUID имеет приоритет), scope и storage kind. InstanceOrType использует type только при отсутствии instance-параметра; дубликаты не разрешаются произвольным выбором. Категории используют BuiltInCategory, не локализованные подписи. Double хранится в внутренних единицах и не допускает numeric range в правилах: единицы требуют отдельного контракта. Integer диапазоны проверяются явно.

Pattern — CultureInvariant Regex с 50 мс timeout; превышение становится отдельным замечанием, а не зависанием. ReferenceRules проверяют строковую ссылку на марку среди заданной категории. Проектные правила не считаются нормативами СКУД или спецификацией Sigur.

## Изменение модели

RevitTransaction выполняет ручной start/action/commit, проверяет статус и собирает ошибки IFailuresPreprocessor. Ошибки откатывают транзакцию; warnings не удаляются. ForcedModalHandling исключает намеренно асинхронную обработку в этом сценарии. Worksharing ownership проверяется до изменения; заимствование/синхронизация не выполняются автоматически.

MarkWriter проверяет все старые значения, доступность, существование и конфликты до записи. SchematicWriter помечает страницы и аннотации отдельной схемой. Повторная генерация удаляет только собственные аннотации. Если у них есть чужие зависимые элементы, обновление блокируется; пользовательские размеры не удаляются каскадно. Лишние старые страницы сохраняются с отметкой об устаревании. Все страницы обновляются одной транзакцией.

Ошибки отдельного действия перехватываются внутри report loop. Возврат Result.Failed в конце команды мог бы откатить ранее успешно выполненные действия; поэтому ошибка позднего экспорта/выделения не превращает всю команду в Failed. Начальная ошибка расчёта по-прежнему возвращает Failed.

Локальные JSONL логи ошибок — %LOCALAPPDATA%/BimPortfolio/logs. Исключения могут содержать пути/параметры; перед публикацией журнал нужно просмотреть. Логирование не должно ломать основное действие при IO/permission error.

## Проверки и поставка

55 domain tests, включая 30 случайных графов/5 880 shortest-path запросов и 300 BVH queries против полного перебора; 13 Presentation tests. Браузер проверяет рендер, выбор, поиск, проекции, mobile overflow, ошибки JS и отсутствие сети. Microbenchmark прогревает оба варианта, берёт медиану трёх батчей и отдельно сравнивает расстояния.

Пять compile targets/API; проверка в хосте остаётся отдельной стадией. API DLL исключены из runtime assets и пакета. Newtonsoft, Core, Revit, Presentation, UI и ru satellite поставляются рядом с DLL плагина. NuGet API — сторонняя compile packaging; официальный installed API поддерживается через RevitApiDir.
